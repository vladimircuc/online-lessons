Variables, Math & Strings

a ← 5Assignment. Arrow, not equals sign.
a ← a + 1Increment. Right side evaluates first, then assigns.
+ - * /Standard math. Division gives decimals (7/2 = 3.5).
a MOD bRemainder. 17 MOD 5 = 2. Even check: n MOD 2 = 0.
"3" + "5"String concatenation = "35" (NOT 8). Quotes = strings.
Swap a, bNeed temp: temp←a, a←b, b←temp. Three steps.

Booleans & Logic

= ≠ > < ≥ ≤Comparison. = checks equality (not assignment).
ANDBoth true → true. Anything else → false.
ORAt least one true → true. Both false → false.
NOTFlips. NOT true = false.
De Morgan'sNOT(A AND B) = NOT A OR NOT B. NOT(A OR B) = NOT A AND NOT B.
Separate IFs vs IF/ELSE: Two IFs both execute independently. IF/ELSE stops at first match. The exam tests this with a first IF that changes a variable, making the second IF see the new value.

Loops

REPEAT n TIMESFixed count. No counter variable. Runs exactly n times.
REPEAT UNTIL(cond)Checks BEFORE each run. Stops when condition becomes true.
FOR EACH x IN listx = the VALUE, not index. Use for reading, not modifying.
REPEAT UNTIL checks before running. If already true, body never executes. If variable never changes inside, infinite loop.
Trace every loop with a table: columns for variables, rows for iterations. Fastest way to avoid mistakes.

Lists (1-Based!)

list[i]Access element at index i. FIRST element = index 1, NOT 0.
LENGTH(list)Number of elements. Last element at list[LENGTH(list)].
APPEND(list, val)Add to END. List grows by 1.
INSERT(list, i, val)Insert at i. Everything at i and after shifts RIGHT.
REMOVE(list, i)Delete at i. Everything after shifts LEFT.
b ← a (lists)Creates a COPY. Modifying b does NOT affect a.
Index shift after REMOVE is the #1 list trap. After removing index 2, old index 3 becomes new index 2.

Procedures & RETURN

PROCEDURE f(x)Define. x = parameter (local). Called with f(5), 5 = argument.
RETURN(val)Sends val back. Exits IMMEDIATELY. Code after = dead.
DISPLAY vs RETURNDISPLAY prints to screen, returns nothing. RETURN sends back, prints nothing.
AbstractionUse procedure by name/params/return only. Don't need internals.
Library / APIPre-built procedures. Use without knowing how they work.

Random, Simulations, Undecidable

RANDOM(a, b)Random integer a to b INCLUSIVE. Count = b-a+1.
SimulationsModel real-world. Cheaper, safer, faster, repeatable. NOT exact.
LimitationSimplifies reality. Different runs → different results.
UndecidableNo algorithm solves it for ALL inputs. Proven impossible.
Halting Problem"Will program P halt on input X?" Cannot be answered in general.

Binary & Number Systems

Place values...128, 64, 32, 16, 8, 4, 2, 1 (right to left, each double)
Binary → DecimalAdd place values where bit = 1. E.g., 1011 = 8+2+1 = 11
Decimal → BinarySubtract largest power of 2 that fits, repeat. Mark those positions as 1.
n bits → values2ⁿ values. Range: 0 to 2ⁿ-1. E.g., 8 bits = 256 values (0-255).
Need N values?Find smallest n where 2ⁿ ≥ N. E.g., 1000 values → 10 bits (1024).
+1 bitDOUBLES the number of representable values.

Overflow & Roundoff

OverflowNumber too LARGE for available bits. 256 in 8-bit (max 255) = overflow.
RoundoffSome decimals infinite in binary. 0.1+0.2 = 0.30000000004. Tiny imprecision.
Overflow = too big. Roundoff = imprecise decimal. Know the difference.

Analog vs Digital

AnalogContinuous. Infinite values. Sound waves, temperature.
DigitalDiscrete. Finite values. MP3, JPEG, text files.
Sampling rateHow often you sample. Higher = better quality = larger file.
Bit depthBits per sample. More bits = more precise = larger file.
Higher quality ALWAYS means larger file. This trade-off is tested constantly.

Data Analysis & Visualization

Data → InformationRaw values → processed/interpreted meaning.
CorrelationTwo variables move together. Does NOT mean one causes the other.
CausationOne directly causes the other. Requires controlled experiment to prove.
Confounding varHidden 3rd factor driving both. Ice cream + drowning ← hot weather.
Truncated y-axis#1 misleading graph trick. Small change looks huge.
MetadataData ABOUT data: file size, date, GPS, device. NOT the content itself.
CORRELATION ≠ CAUSATION. This is the most tested concept in BI2. If a question says "data shows X and Y are related," the valid conclusion is correlation, NOT causation.

Effects of Computing

Every innovationHas BOTH beneficial AND harmful effects. Always both sides.
IntendedWhat the technology was designed to do.
UnintendedSide effects nobody planned. Echo chambers, job loss, etc.

Digital Divide

DefinitionGap between those with and without access to computing/internet.
CausesIncome, geography (rural), age, disability, developing nations.
ConsequenceReinforces existing inequalities. Those behind fall further behind.
SolutionsPublic Wi-Fi, device programs, broadband subsidies, accessibility design.

Computing Bias

SourceBiased training data, biased programmers, exclusion from datasets.
ExamplesFacial recognition (race), hiring algorithms (gender), predictive policing.
Proxy discriminationZip code as proxy for race/income. Algorithm isn't "racist," data reflects bias.
FixAudit for disparate impact, diversify data, human oversight.

Crowdsourcing

DefinitionLarge group contributions online. Wikipedia, Waze, Kickstarter, reCAPTCHA.
BenefitsScale, diverse perspectives, low cost per contributor.
LimitsQuality varies, can be manipulated, not representative of all groups.

Legal & Ethical

CopyrightAutomatic on creation. All rights reserved. Can't use without permission.
Creative CommonsSome rights reserved. BY=credit, SA=share-alike, NC=non-commercial, ND=no derivatives.
Open SourceSource code public. Still has license (MIT, GPL). Not "no copyright."
Public DomainNo copyright. Completely free to use. Old works, explicit dedication.

PII & Security

PIIName, email, SSN, IP address, GPS, biometrics, browsing history.
Symmetric encryptionOne key for encrypt + decrypt. Fast. Problem: sharing the key securely.
Public keyTwo keys: public encrypts, private decrypts. Solves key-sharing problem.
PhishingFake messages to steal credentials. Targets HUMANS, not technology.
RansomwareEncrypts your files, demands payment. Paying doesn't guarantee recovery.
MFATwo+ factors from DIFFERENT categories: know (password), have (phone), are (fingerprint).
Two passwords = NOT MFA (both "something you know"). Password + SMS code = MFA (know + have).
Digital footprintActive: you post it. Passive: collected without your action (IP logs, cookies).
PermanenceEssentially permanent. Deleted ≠ gone (screenshots, caches, backups).

The Internet

InternetNetwork of networks. Physical infrastructure. Decentralized, no single owner.
WWWWeb pages via HTTP. Runs ON the internet but is NOT the internet.
Open protocolsNon-proprietary standards. Any device from any manufacturer can connect.

Protocols

ProtocolWhat It Does
IPAddresses devices, routes packets. IPv4=32-bit (~4.3B), IPv6=128-bit (unlimited).
TCPReliable delivery. Numbers packets, checks arrival, resends lost ones, reassembles in order.
HTTP/HTTPSWeb page requests. HTTPS adds encryption (TLS/SSL). S = Secure.
DNSTranslates domain names → IP addresses. "Phone book" of the internet.
IP = where to send it (addressing). TCP = making sure it all arrives (reliability). DNS = looking up the address. HTTPS = keeping it private (encryption).

Packets & Routing

PacketsData broken into small pieces. Each has: data + source IP + dest IP + sequence #.
Independent routingPackets travel independently, may take different paths, may arrive out of order.
ReassemblyTCP uses sequence numbers to put packets back in correct order at destination.

Fault Tolerance

DefinitionSystem keeps working even when part fails. Through REDUNDANCY.
RedundancyMultiple paths between points. If one fails, data reroutes.
Single point of failureRemove one thing and part of the network is disconnected. NOT fault-tolerant.
For network diagrams: trace alternate paths. If NO alternate path exists after removing a connection, it's not fault-tolerant for that failure.

Parallel & Distributed Computing

SequentialTasks one after another. Total = sum of all task times.
ParallelIndependent tasks simultaneously. Limited by sequential portions.
SpeedupSequential time / Parallel time. Can't go below sequential portion's time.
DistributedMultiple machines via network. Solves problems too large for one machine.
Even with infinite processors, sequential parts take the same time. That's the hard limit on speedup.

Program Design

PurposeWHY the program exists. What problem it solves. Who it helps.
FunctionWHAT the program does technically. The specific behavior.
CollaborationDiverse perspectives, code review, pair programming. Catches more bugs.
Version controlGit. Tracks changes, allows simultaneous work, prevents overwriting.

Error Types

TypeWhenSymptomExample
SyntaxBefore runningWon't run at allMissing parenthesis, misspelled keyword
LogicDuring runningWrong output, no crashUsing + instead of *, off-by-one loop
RuntimeDuring runningCrashes midwayDivide by zero, index out of bounds
Logic errors are the hardest to find because the program runs fine, no error message, just quietly gives wrong results. Only caught by testing.

Development & Testing

IterativePlan → Code → Test → Evaluate → Repeat. Small cycles, not all at once.
Boundary testingTest at edges. For 1-100: test 0, 1, 50, 100, 101.
Edge casesEmpty list, single element, negative numbers, very large values.
DocumentationComments explain WHY, not just WHAT. Helps future you and others.

Describe: purpose (WHY), function (WHAT), inputs, outputs. Purpose = problem solved, not code behavior.

Walk through procedure showing sequencing, selection, iteration. EXPLAIN each, don't just name them. Reference specific code lines.

WR 2(b): Errors & Testing (1 pt, ~60% earn it)

Two test calls with EXACT argument values and EXACT expected results. "I tested with different inputs" = 0 points.

WR 2(c): Data & Procedural Abstraction (1 pt, ~49% earn it)

How list manages complexity. MUST include: "Without the list, I would need..." comparison. Explain storage AND usage.

Common Mistakes (From Chief Reader)

Naming without explaining: "My code has sequencing, selection, and iteration." WALK THROUGH each one with specific code.
Vague testing: "I tested with different inputs." Give EXACT argument values and EXACT expected results.
Missing complexity argument: Explain what the list stores, but also what your code would look like WITHOUT it (separate variables, duplicated logic).
Confusing purpose and function: Purpose = help students organize homework. Function = sorts list and displays colored text.
