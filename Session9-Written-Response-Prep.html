PPR Procedure Segment 1: Your Student-Developed Procedure

def process_and_display_tasks(tasks, current_day):
    tasks.sort()                    ← SEQUENCING
    y_position = 150

    for item in tasks:              ← ITERATION
        year, month, day, task_name = item
        display_string = str(year)+"/"+str(month)+"/"+str(day)+" - "+task_name
        task_display = Text(display_string)
        task_display.set_position(70, y_position)

        is_correct_time = (year == today_year and month == today_month)
        days_left = day - current_day

        if is_correct_time and 0 <= days_left <= 3:  ← SELECTION
            task_display.set_color("#F54927")    ← urgent (red)
        else:
            task_display.set_color("#00334d")    ← not urgent (blue)

        task_display.set_font("11pt Monospace")
        add(task_display)
        y_position += 35

3. The 4 Prompts Explained

The exact wording changes each year, but the categories are always the same. Here's what each one is really asking.

Written Response 1: Program Design, Function & Purpose 1 PT

78-84% earned this in 2025

This asks about the BIG PICTURE of your program. Not how the code works, but WHY it exists and WHO it helps.

What They're Really Asking
Describe your program's purpose (what problem does it solve?), the functionality (what does it do?), and the input/output (what goes in and what comes out?).
Purpose = the problem it solves (helping students organize homework)
Function = what it actually does (collects tasks, sorts by date, shows them)
Input   = what the user provides (task names, due dates, today's date)
Output  = what the user sees (sorted list with urgent items in red)

Written Response 2(a): Algorithm Development 1 PT

43-45% earned this in 2025

This asks you to WALK THROUGH your procedure's algorithm, identifying sequencing, selection, and iteration and explaining how they work TOGETHER.

What They're Really Asking
Using your procedure code, explain the algorithm. Point to specific lines that show sequencing, selection, and iteration. Explain what each part DOES and how it contributes to the procedure's overall functionality.
#1 reason students lose this point: Just listing "my code has sequencing, selection, and iteration" WITHOUT walking through how each one works in the code. You must explain the MECHANICS, not just name the concepts.

Written Response 2(b): Errors and Testing 1 PT

57-62% earned this in 2025

This asks about how you tested your code OR asks you to identify/describe errors. You need SPECIFIC test cases with ACTUAL VALUES.

What They're Really Asking
Describe two calls to your procedure with different arguments that test different behavior. For each call, state the specific argument values and the expected result.
#1 reason students lose this point: Writing vague answers like "I tested with different inputs and it worked." You MUST give exact values and exact expected results.

Written Response 2(c): Data & Procedural Abstraction 1 PT

40-57% earned this in 2025

This asks how your list manages complexity and/or how your procedure provides abstraction. The key phrase is "manages complexity."

What They're Really Asking
Explain how the list stores data AND how it's used. Then explain what your code would look like WITHOUT the list and why that would be worse. This is the "manages complexity" argument.
#1 reason students lose this point: Explaining WHAT the list stores but NOT explaining HOW it manages complexity. You need the comparison: "Without the list, I would need..." to earn the point.

4. Practice: Written Response 1

Write Your Response (Purpose, Function, Input/Output)

Prompt: Describe the overall purpose of your program, what problem it solves, and identify the program's input(s) and output(s).

Write your answer first, THEN reveal the model answer to compare.

Model Answer (Full Credit)

My program is a Homework Planner designed to help students organize and keep track of their assignments. The purpose is to solve the problem of students forgetting or missing homework deadlines by providing a visual, sorted display of upcoming tasks with urgency indicators.

The program takes several inputs from the user: their name, the current date (day, month, year), and for each homework task, the due date (year, month, day) and a description of the assignment. Users can add as many tasks as they want through a loop that asks if they want to add another.

The program outputs a sorted homework planner displayed on a graphical canvas. Tasks are sorted chronologically by due date. Tasks that are due within 3 days of the current date are displayed in red to indicate urgency, while other tasks are displayed in dark blue. This visual distinction helps students quickly identify which assignments need immediate attention.

WHY THIS EARNS THE POINT: It clearly states the purpose (organizing homework, preventing missed deadlines), identifies specific inputs (name, date, task details) and outputs (sorted color-coded list), and explains the functionality (sorting, urgency coloring). It goes beyond just describing what the code does and explains the real-world problem it solves.

5. Practice: Written Response 2(a)

Write Your Response (Algorithm: Sequencing, Selection, Iteration)

Prompt: Refer to your Personalized Project Reference. Describe the algorithm implemented in your procedure. Identify where sequencing, selection, and iteration are used and explain how they work together to achieve the procedure's functionality.

Refer to your procedure screenshot. Write your answer first, THEN reveal.

Model Answer (Full Credit)

My procedure process_and_display_tasks(tasks, current_day) implements an algorithm that sorts homework tasks and displays them with urgency-based color coding.

Sequencing is used at the beginning of the procedure where tasks.sort() sorts the entire list chronologically, and then y_position = 150 initializes the vertical position for displaying tasks on the canvas. These steps must happen in this order because the list must be sorted before it is displayed.

Iteration is used with the for item in tasks loop, which processes every task in the list one at a time. For each task, it unpacks the year, month, day, and task name from the tuple, builds a display string, and positions it on the canvas. The loop also increments y_position by 35 each time so tasks appear stacked vertically.

Selection is used inside the loop with the if/else statement. It checks whether the task is due within the current month and within 3 days of the current date using is_correct_time and 0 <= days_left <= 3. If true, the task is displayed in red to show urgency. Otherwise, it is displayed in dark blue. This creates two different code paths depending on the due date.

These three work together: sequencing sets up the sorted data, iteration processes each task, and selection determines the color for each individual task within that loop.

WHY THIS EARNS THE POINT: It doesn't just list the three concepts, it walks through each one with specific code references (tasks.sort(), for item in tasks, if/else), explains what each part DOES, and ties them together with a closing sentence about how they work as a system. This is what the 55% of students who lost this point in 2025 failed to do.

6. Practice: Written Response 2(b)

Write Your Response (Testing with Specific Values)

Prompt: Describe two calls to your procedure with different arguments that produce different results. For each call, describe the arguments used and the expected result.

Give SPECIFIC values for each test. Write your answer first, THEN reveal.

Model Answer (Full Credit)

Test Call 1 (Urgent task): I call process_and_display_tasks([(2026, 5, 15, "Math HW")], 13) where the tasks list contains one task due May 15, 2026, and current_day is 13. Since today_month matches the task's month and days_left = 15 - 13 = 2, which is between 0 and 3, the condition is_correct_time and 0 <= days_left <= 3 is true. The expected result is that "2026/5/15 - Math HW" is displayed in red (#F54927), indicating it is urgent.

Test Call 2 (Non-urgent task): I call process_and_display_tasks([(2026, 6, 20, "Science Project")], 13) where the tasks list contains one task due June 20, 2026, and current_day is 13. Since the task's month (6) does not match today_month (5), is_correct_time is false. The condition fails, so the else branch runs. The expected result is that "2026/6/20 - Science Project" is displayed in dark blue (#00334d), indicating it is not urgent.

WHY THIS EARNS THE POINT: Each test has SPECIFIC argument values (exact list contents, exact current_day), traces the logic (which condition is true/false and why), and states the SPECIFIC expected output (text displayed in which color). Compare this to a weak answer: "I tested with an urgent task and a non-urgent task and both worked correctly." That vague answer earns 0 points.

7. Practice: Written Response 2(c)

Write Your Response (List Manages Complexity / Abstraction)

Prompt: Refer to your Personalized Project Reference. Explain how the list in your code manages complexity in your program. Explain what your program would look like without the list and why that would be more complex.

Explain what the list stores, how it's used, and what you'd need WITHOUT it. Write first, THEN reveal.

Model Answer (Full Credit)

My program uses homework_list, a list that stores tuples of (due_year, due_month, due_day, task_description) for every homework assignment the user enters. The list manages complexity because it allows the program to handle any number of tasks using the same code.

In the storage segment, a while loop appends each new task as a tuple to homework_list. In the usage segment, process_and_display_tasks iterates over the entire list with a for loop, unpacking each tuple to build the display string and check urgency for every task.

Without the list, I would need separate variables for each task, like task1_year, task1_month, task1_day, task1_name, then task2_year, task2_month, task2_day, task2_name, and so on. I would also need to duplicate the sorting and display code for each individual task. If a student had 10 homework assignments, I would need 40 separate variables and 10 copies of the display logic. The program would be unable to handle a flexible number of tasks because the number of variables would be fixed at the time the code was written. The list solves this by storing all tasks in one structure that grows dynamically and can be processed with a single loop.

WHY THIS EARNS THE POINT: It explains what's stored (tuples with date + description), how it's used (iteration, unpacking, sorting), and critically, what the code would look like WITHOUT the list (40 separate variables for 10 tasks, duplicated logic, fixed capacity). That "without the list" comparison is what most students forget, and it's what the rubric means by "manages complexity."

8. Top Mistakes to Avoid

From the College Board Chief Reader Reports

MISTAKE 1: Naming without explaining
  ❌ "My procedure uses sequencing, selection, and iteration."
  ✅ Walk through EACH one with specific code references.

MISTAKE 2: Vague testing
  ❌ "I tested with different inputs and it worked."
  ✅ "I called process_and_display_tasks with [(2026,5,15,'Math')], 13
      and the task displayed in red because days_left = 2."

MISTAKE 3: Describing the list without the "manages complexity" argument
  ❌ "My list stores homework tasks as tuples."
  ✅ "Without the list, I would need 40 separate variables for 10 tasks
      and duplicate display code for each one. The list lets me handle
      any number of tasks with one loop."

MISTAKE 4: Confusing purpose and function
  ❌ Purpose: "My program sorts a list and displays text."
  ✅ Purpose: "My program helps students organize homework so they
      don't miss deadlines."
  (Purpose = WHY it exists. Function = WHAT it does technically.)

MISTAKE 5: Not referencing your actual code
  ❌ Generic answers that could apply to any program.
  ✅ Reference YOUR variables (homework_list, tasks, current_day),
      YOUR functions (process_and_display_tasks), and YOUR logic
      (the urgency color check).
Final tip: Your answers don't need to be long. They need to be SPECIFIC. A 4-sentence answer that names exact variables, exact values, and exact behavior beats a 10-sentence vague paragraph every time. Quality of detail, not quantity of words.
