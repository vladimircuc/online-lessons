    Module 01 · Session 08, Part A

    JavaScript, the behavior layer.

    JavaScript is a dynamic programming language that web browsers can interpret. Most often it is used to create dynamic web interfaces, things that respond when a user interacts. HTML is structure, CSS is appearance, JavaScript is behavior.

    Talking points

    The mental model: HTML is the skeleton, CSS is skin and clothes, JavaScript is the muscles and brain. Without JS, the page just sits there.

    Three places JS can live: external file (cleanest, what we'll do), embedded in a script tag, or inline as an attribute. We'll use embedded for simplicity, but in production you'd use external files.

    Six core concepts covered in the prof's syllabus: variables, data types, operators, conditionals, loops, functions. We'll touch the first two and functions today, plus the click handler pattern that ties it all together.

    Pronunciation DOM "dom" (rhymes with mom) console "KON-sole"

    The three places JavaScript lives

    1. External file (recommended for real projects)

    Put your JS in a separate .js file and link it. Keeps HTML clean.

    <script src="js/myscript.js"></script>

    2. Embedded in the page (what we'll use today)

    Put your JS directly inside a script tag. Fine for small projects and learning.

    <script>
  alert("Hello!");
</script>

    3. Inline (avoid for anything serious)

    Stuck inside an HTML attribute. Hard to maintain.

    <button onclick="alert('Hi!');">Click me</button>

    Add your first script

    →
    In index.html, find the closing </body> tag near the bottom. Add this <script> block just above it.
    index.html · just before </body> 
    <script>

  // console.log writes a message to the browser's developer console.
  // Useful for debugging. Doesn't show on the page itself.
  console.log("Hello from JavaScript!");

  // alert pops up a dialog box. Annoying for users, fine for testing.
  alert("The page is alive.");

</script>
    What happens after save and refresh

    An alert popup appears with the text "The page is alive." Close it.

    If you open the developer console (right-click anywhere on the page, choose Inspect, click the Console tab), you'll see the line "Hello from JavaScript!" printed there.

    Variables and functions

    The two most fundamental JavaScript concepts: variables store values, functions store actions.

    JavaScript · variables 
    // "let" creates a variable whose value can change later
let count = 0;
count = count + 1;       // now count is 1

// "const" creates a variable whose value cannot be reassigned
const name = "Jack";

// Variables can hold different types of data:
let age = 21;            // number
let isStudent = true;    // boolean (true or false)
let hobbies = ["design", "music"];   // array (a list)
    JavaScript · functions 
    // A function is a packaged set of instructions you can run later.
// Define it once with the "function" keyword, run it as many times as you want.
function sayHi() {
  alert("Hi!");
}

// Calling the function actually runs the code inside it
sayHi();   // popup appears
sayHi();   // popup appears again

    The whole point: react to a click

    This is the move that actually makes pages interactive. Pick an element, listen for an event (like a click), run a function.

    1
    In index.html, find the About section. Add a button right after the paragraph.
    index.html · inside the About section 
    <section id="about">
  <h2>About</h2>
  <p>I am a designer studying at The College of New Jersey. I make
     websites, posters, and the occasional zine.</p>

  <!-- New: a button with an id so JavaScript can find it -->
  <button id="surprise-btn">Click for a surprise</button>
</section>
    2
    Replace your <script> tag at the bottom with this one.
    index.html · the <script> tag 
    <script>

  // STEP 1: find the button on the page.
  // document.getElementById takes an id string, returns the matching element.
  const btn = document.getElementById("surprise-btn");

  // STEP 2: listen for a click on that button.
  // addEventListener takes two things: the event name ("click")
  // and a function to run whenever that event happens.
  btn.addEventListener("click", function() {

    // STEP 3: this code runs every time the button is clicked.
    alert("Surprise! You clicked the button.");

  });

</script>
    What happens after save and refresh

    You'll see a button under the About paragraph. Clicking it triggers a popup with the text "Surprise! You clicked the button." Close it. Click again. Same thing happens. The function runs every time the click event fires.

    This three-step pattern (find element, listen for event, do something) is the entire core of interactive JavaScript. Everything else builds on it.

    Quick check
    Why do we put the <script> tag at the bottom of the body, not in the head?
    Right answer: B. If the script runs before the HTML exists, document.getElementById("surprise-btn") returns nothing because the button hasn't been created yet. Putting the script at the bottom guarantees the page is fully built before JS runs.
    Quick check
    What does addEventListener("click", ...) do?
    Right answer: C. An event listener listens for an event (click, hover, keypress, etc.) and runs your function when it happens.
    Module 02 · Session 08, Part B

    jQuery, the easy mode.

    jQuery is a cross-browser JavaScript library designed to simplify common tasks: selecting elements, handling events, animations, special effects. It's old now, but your prof wants you to know it because it's still everywhere on the web.

    Talking points

    jQuery's pitch: "this thing that takes 4 lines of vanilla JS, jQuery does in 1." That's it. It's a wrapper that makes common tasks shorter to write.

    To use it, you load the jQuery library from a CDN (a fast file host), then you can use the magic $ symbol as a shortcut to grab elements and do things with them.

    Modern frameworks (React, Vue) have replaced jQuery for most new work, but knowing it is still required because tons of existing sites and plugins use it.

    Pronunciation jQuery "jay-QUEER-ee" CDN "see-dee-EN" (each letter)

    See the difference: vanilla vs jQuery

    Same task, two ways to write it. Click the toggle to compare.

    // Find the button
const btn = document.getElementById("surprise-btn");

// Find the about section
const about = document.getElementById("about");

// Add click listener
btn.addEventListener("click", function() {
  // Toggle the "highlighted" class on the about section
  about.classList.toggle("highlighted");
});
    // Same thing, in jQuery:
$("#surprise-btn").on("click", function() {
  $("#about").toggleClass("highlighted");
});

    Same result, fewer lines. The trade-off is loading an extra library, but for school projects and small sites that's fine.

    Add jQuery to the page

    You don't install anything. You link to a hosted version using a script tag, the same way you'd link external CSS.

    →
    In index.html, replace your existing <script> at the bottom with these two script tags.
    index.html · just before </body> 
    <!-- Load the jQuery library from a CDN. This must come BEFORE your code. -->
<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>

<!-- Your code that uses jQuery -->
<script>

  // $(document).ready(...) is jQuery's way of saying:
  // "wait until the page is fully loaded, then run this code."
  $(document).ready(function() {

    // $("#surprise-btn") is jQuery's shortcut for getElementById.
    // .on("click", ...) attaches a click listener.
    $("#surprise-btn").on("click", function() {

      // $("#about") finds the about section.
      // .toggleClass("highlighted") adds the class if missing,
      // removes it if present. Perfect for on/off effects.
      $("#about").toggleClass("highlighted");

    });

  });

</script>
    →
    In styles.css, add the highlighted class so the toggle has something to do.
    styles.css · add to the bottom 
    /* When this class is on the section, give it a yellow background.
   The transition makes the color change fade in instead of jumping. */
.highlighted {
  background: #fff3a0;
  padding: 16px;
  border-radius: 4px;
  transition: background 0.3s;
}
    What happens after save and refresh

    Click the surprise button. The About section turns yellow. Click again, it turns back to normal. .toggleClass() flips the class on and off each time.

    jQuery selectors: same as CSS

    If you can write a CSS selector, you already know jQuery selectors. Same exact syntax inside the $().

    jQuery selectors · reference 
    $("h2")              // every <h2> on the page
$("#about")          // the element with id="about"
$(".photos")         // every element with class="photos"
$(".photos img")     // every <img> inside .photos
$("nav a")           // every <a> inside <nav>
$("input[type=email]")   // every email input

    Common jQuery methods

    Once you've selected something with $(), you can chain methods to read or change it.

    jQuery methods · reference 
    // CHANGE TEXT
$("h1").text("New name");          // replaces the text inside h1

// CHANGE HTML (text + tags)
$("#about").html("<em>italic</em>");

// CHANGE CSS DIRECTLY
$("h1").css("color", "red");
$("h1").css({ color: "red", fontSize: "40px" });

// ADD / REMOVE / TOGGLE CLASSES
$("#about").addClass("highlighted");
$("#about").removeClass("highlighted");
$("#about").toggleClass("highlighted");

// SHOW / HIDE
$("#about").hide();
$("#about").show();
$("#about").fadeOut();    // animated
$("#about").fadeIn();     // animated

// CHAIN MULTIPLE METHODS TOGETHER
$("h1").css("color", "red").text("Boom").addClass("loud");
    Quick check
    What does $("#gallery").toggleClass("highlighted") do?
    Right answer: C. That's what "toggle" means. It flips between on and off. Useful for dark mode buttons, opening menus, showing/hiding panels.
    Quick check
    Why do we wrap our code in $(document).ready(...)?
    Right answer: B. Same problem as before, just packaged differently. If we try to grab #surprise-btn before it exists, we get nothing.
    Module 03 · Session 08, Assignment

    An image gallery plugin.

    A jQuery plugin is jQuery code that someone else wrote, packaged up, and shared so you can drop it into your page. Your Session 8 assignment is to add a real image gallery using a plugin. We'll use Swiper.js, a popular free slider library.

    Talking points

    The pattern for any plugin is always the same four steps: link the CSS file, link the JS file, write the HTML structure the plugin expects, then activate the plugin with one line of JavaScript.

    Once Jack understands this pattern, he can use any plugin. Swiper, Slick, Lightbox, Fotorama, all of them follow this exact pattern.

    Pronunciation Swiper "SWY-per" CDN "see-dee-EN"

    The four-step plugin pattern

    1
    Link the plugin's CSS
    Goes in the <head>, brings in the plugin's styles.
    2
    Link the plugin's JavaScript
    Goes near </body>, brings in the plugin's behavior.
    3
    Write the HTML structure
    Each plugin expects specific class names and nesting. Read the docs.
    4
    Activate the plugin
    One line of JavaScript that tells the plugin which element to take over.

    Step 1, link Swiper's CSS

    Step 4, activate the plugin

    4
    Update your custom script (the one with $(document).ready) to also activate Swiper.
    index.html · your script tag 
    <script>
  $(document).ready(function() {

    $("#surprise-btn").on("click", function() {
      $("#about").toggleClass("highlighted");
    });

    // ACTIVATE SWIPER
    // The string ".my-gallery" tells Swiper which element to turn into a slider.
    // The object after it is configuration: which features to enable.
    new Swiper(".my-gallery", {
      loop: true,                              // wrap around at the end
      navigation: {
        nextEl: ".swiper-button-next",         // which element is the "next" button
        prevEl: ".swiper-button-prev",         // which element is the "prev" button
      },
      pagination: {
        el: ".swiper-pagination",              // where to render the dots
        clickable: true,                       // dots can be clicked to jump
      },
    });

  });
</script>

    Module 04 · Session 09

    Forms that actually work.

    HTML forms allow you to capture user input and use it in your application, pass it to other applications (like mail servers), or save it for later. Login forms, contact forms, comment forms, search bars, all forms.

    Talking points

    Every form input you've ever seen on the web is one of about 8 HTML elements: form, input, textarea, select, label, fieldset, legend, button.

    The big concept: by default, when you submit a form, the browser tries to reload the page and send data to a server. For a portfolio site without a backend, we use JavaScript to intercept that submit and just show a thank-you message. The prof also mentions FormSpree.io as a free way to actually receive form submissions via email.

    Form elements cheat sheet

    HTML · form elements 
    <!-- The wrapper. Everything goes inside. -->
<form>...</form>

<!-- Single-line text input. The "type" changes the keyboard
     and validation: text, email, tel, url, number, password, date, etc. -->
<input type="text">

<!-- Multi-line text input. Use rows to set the visible height. -->
<textarea rows="5"></textarea>

<!-- Dropdown menu -->
<select>
  <option value="design">Design</option>
  <option value="code">Code</option>
</select>

<!-- Label connects to an input via matching for/id.
     Click the label, the input gets focused. -->
<label for="email">Email</label>
<input type="email" id="email">

<!-- Submit button. Type=submit makes Enter submit the form. -->
<button type="submit">Send</button>

    Catch the submit with JavaScript

    Right now the form will try to reload the page when submitted. We use JavaScript to stop that and show a success message instead.

    3
    Inside your $(document).ready(...) block, add this new section.
    index.html · inside $(document).ready 
    // Listen for the form's "submit" event.
// This fires when the user clicks the submit button OR presses Enter in a field.
$("#contact-form").on("submit", function(event) {

  // STOP THE BROWSER'S DEFAULT BEHAVIOR.
  // Without this, the page reloads and tries to send data to a server.
  event.preventDefault();

  // Read what the user typed into each field.
  // .val() is jQuery's shortcut to get an input's current value.
  const name = $("#name").val();
  const email = $("#email").val();
  const message = $("#message").val();

  // Log the data to the console so we can see it (great for testing).
  console.log("Form submitted:", { name, email, message });

  // Hide the form, show the success message.
  $("#contact-form").hide();
  $("#form-success").show();

});
    What happens after save and refresh

    You see a clean form with three fields and a Send button. Try submitting it empty, the browser blocks you because of required. Type something invalid into the email field, the browser blocks that too because of type="email".

    Fill it out properly and click Send. The form disappears, replaced by "Thanks, your message has been sent." Open the browser console (F12), you'll see the logged data.

    Quick check
    What does event.preventDefault() do in a form submit handler?
    Right answer: C. Without it, the browser reloads the page. With it, you stop that and decide what happens (show a message, send an AJAX request, animate, whatever).
    Quick check
    Why does <label for="email"> need to match <input id="email">?
    Right answer: B. Matching IDs link the label to the input. Screen readers announce the label when the input is focused, and clicking the label moves focus to the input.
    Module 05 · Session 10

    CSS Grid layouts.

    CSS Grid Layout is the most powerful layout system available in CSS. It is a 2-dimensional system, meaning it can handle both columns and rows, unlike flexbox which is largely 1-dimensional. You apply CSS rules both to a parent (the Grid Container) and to its children (the Grid Items).

    Talking points

    Two key concepts: parent (Grid Container) and children (Grid Items). Set display: grid on the parent, then describe the structure with grid-template-columns and grid-template-rows.

    The fr unit is the magic. It means "fraction of available space." 1fr 1fr 1fr = three equal columns. 2fr 1fr = first column twice as wide as the second.

    Use the interactive demo below to show Jack how fr units split space proportionally.

    Pronunciation fr "eff-arr" or "fraction" repeat "ree-PEAT"

    Visualize fr units

    Drag the sliders to change the fr values. Watch how the columns redistribute.

    C

    In styles.css, add this to the bottom.

    Make it responsive with one trick

    Three columns looks fine on desktop, terrible on mobile. The repeat() + auto-fit + minmax() combo is the industry standard way to make a grid that adapts automatically without media queries.

    →
    In styles.css, replace your grid-template-columns line with this.
    styles.css · the .photo-grid rule 
    .photo-grid {
  display: grid;

  /* repeat(): "make a bunch of columns following this pattern"
     auto-fit:  "as many as fit in the available space"
     minmax(180px, 1fr): "each column is at least 180px wide,
                          but can grow up to 1fr to share leftover space" */
  grid-template-columns: repeat(auto-fit, minmax(180px, 1fr));

  gap: 12px;
  margin-top: 24px;
}
    What happens after save and refresh

    The grid now has as many columns as fit. On a wide desktop browser, you might see 4 columns. On a phone, it drops to 1 or 2. Resize your browser window slowly to watch it adapt. No media queries required.

    Quick check
    What does grid-template-columns: 1fr 2fr 1fr mean?
    Right answer: B. The fr unit splits available space proportionally. 1 + 2 + 1 = 4 parts total, so the columns get 25%, 50%, 25%.
    Quick check
    In repeat(auto-fit, minmax(180px, 1fr)), what does auto-fit do?
    Right answer: B. auto-fit is what makes the layout responsive without media queries. The browser checks available space and creates as many columns as can fit while respecting the minimum width.

    CSS Custom Properties (a.k.a. Variables).

    CSS Custom Properties are a way to abstract complexity. Define a value once, reference it everywhere with var(). Change the variable, the whole site updates. They make sites easier to maintain and they make features like dark mode trivial.

    Talking points

    You define variables on :root, the pseudo-class for the document root (basically the <html> element). You use them with the var() function. Variable names always start with two hyphens.

    The killer use case: theming. Instead of writing color: #FF6B47 in 40 places, you write it once as --accent: #FF6B47 and use color: var(--accent) everywhere. To rebrand the site, change one line.

    Use the interactive demo below to show Jack how changing a variable cascades through the page instantly.

    Watch variables cascade

    Change the swatches below to see how every element using var(--accent) updates at once.

    #fafaf7
    #222222
    #b94e2c

    Sample card

    This card uses three variables. Try changing them.

    Define your design tokens

    1
    In styles.css, add this at the very top, before everything else.
    styles.css · top of file 
    /* :root is the entire HTML document.
   Variables defined here are accessible to any rule below. */
:root {

  /* Naming convention: every variable starts with -- (two dashes) */
  --bg: #fafaf7;
  --text: #222222;
  --accent: #b94e2c;
  --border: #cccccc;

  /* Variables aren't just for colors. Spacing, sizes, anything: */
  --radius: 4px;
  --space: 16px;
}

    Use the variables

    2
    In styles.css, replace your existing body, header, and nav a rules with these versions that use the variables.
    styles.css · replace existing rules 
    body {
  font-family: Georgia, serif;
  max-width: 720px;
  margin: 0 auto;
  padding: 32px 24px;

  /* var(--name) reads the variable's current value */
  color: var(--text);
  background: var(--bg);
}

header {
  border-bottom: 2px solid var(--text);
  padding-bottom: var(--space);     /* uses the spacing variable */
  margin-bottom: 32px;
}

nav a {
  margin-right: 18px;
  color: var(--text);
  text-decoration: none;
  border-bottom: 1px solid transparent;
}

/* On hover, the underline becomes the accent color.
   This single line is now your brand color, controlled from one place. */
nav a:hover {
  border-bottom-color: var(--accent);
  color: var(--accent);
}

    The payoff: a dark mode toggle

    Now that everything reads from variables, dark mode is just swapping the variable values. We add a class to <body> that overrides them.

    3
    In styles.css, add this below your :root block.
    styles.css · below :root 
    /* When body has the .dark class, redefine the variables.
   Every rule that uses var(--bg), var(--text), var(--accent)
   automatically picks up these new values. No other CSS changes needed. */
body.dark {
  --bg: #1a1a1a;
  --text: #f0f0f0;
  --accent: #ff8c66;
  --border: #444;
}
    4
    In index.html, add a theme toggle button in the header next to the nav.
    index.html · inside <header> 
    <header>
  <h1>Jack Kennedy</h1>
  <nav>
    <a href="#about">About</a>
    <a href="#gallery">Gallery</a>
    <a href="#contact">Contact</a>
  </nav>

  <!-- New: the theme toggle button -->
  <button id="theme-toggle">Dark mode</button>
</header>

    Inside your $(document).ready(...) block, add the toggle handler.
    index.html · inside $(document).ready

  $("body").toggleClass("dark");

  // Update the button label so users know what it'll do next.
  // .hasClass returns true/false depending on whether the class is there.
  if ($("body").hasClass("dark")) {
    $(this).text("Light mode");
  } else {
    $(this).text("Dark mode");

    The header now has a "Dark mode" button. Click it. The entire page swaps to dark colors instantly. The button label changes to "Light mode." Click it again to flip back.

    Important: notice that we didn't write any CSS rules for "what dark mode looks like for the header" or "for nav links." We just changed the variable values. Every rule that uses those variables updated automatically.

    Quick check
    What is the syntax for using a CSS variable in a property?
    Right answer: C. You define a variable with --name: value and you use it with var(--name). Two different syntaxes, easy to mix up at first.
    Quick check
    Why does adding body.dark { --bg: #1a1a1a } change the background everywhere?
    Right answer: B. CSS variables follow normal cascade rules. When body has the dark class, its variable values override the ones on :root, and any rule using var(--bg) picks up the new value.

    SVG, the secret weapon.

    SVG (Scalable Vector Graphics) defines vector-based web graphics in XML format. In HTML5 you can embed SVG elements directly into your HTML pages. Unlike a JPG or PNG, SVG stays sharp at any size, can be styled with CSS, and can be animated.

    Talking points

    SVG is just markup, like HTML. You can paste it directly into your page. Three ways to add SVG to a page: as inline <svg> markup, as the source of an <img> tag, or as a CSS background image. Inline is the most powerful because you can style and animate it with CSS.

    The basic shapes you'll use most: circle, rect, line, path, text. Use the slider demo below to see how the circle's parameters work.

    Important: since SVG is XML, every tag must be properly closed. Self-closing tags use the slash like <circle ... />.

    Pronunciation SVG "ess-vee-JEE" viewBox "VYOO-box"

    Play with an SVG circle

    SVG basic shapes cheat sheet

    SVG · all the basic shapes 
    <!-- Rectangle: x, y are the top-left corner -->
<rect x="10" y="10" width="40" height="40" fill="orange"/>

<!-- Circle: cx, cy = center; r = radius -->
<circle cx="25" cy="25" r="20" fill="teal"/>

<!-- Ellipse: like circle but with two radii -->
<ellipse cx="25" cy="25" rx="20" ry="10" fill="purple"/>

<!-- Line: from (x1,y1) to (x2,y2). Stroke is required. -->
<line x1="0" y1="0" x2="50" y2="50" stroke="black"/>

<!-- Polygon: a closed shape from a list of points -->
<polygon points="25,5 45,45 5,45" fill="crimson"/>

<!-- Text: x, y is the baseline of the first character -->
<text x="10" y="30" font-size="14">Hello</text>

    For complex shapes (curves, irregular outlines), use <path>. You don't write paths by hand: you make them in Illustrator, Figma, or Boxy SVG, then export to SVG.

    Quick check
    What does the viewBox attribute on an SVG define?
    Right answer: B. viewBox is the virtual canvas. The actual rendered size comes from width/height attributes or CSS. The SVG scales whatever you drew in the viewBox to fit the rendered size, which is why SVGs stay sharp at any size.
    Quick check
    Why is stroke="currentColor" useful?
    Right answer: B. Inline SVGs respect CSS, including the special currentColor keyword. Your icon automatically matches whatever text color is in effect, including theme changes and hover states.

    Web animation.

    Animation makes a site feel alive. The two main tools: CSS transitions (smooth interpolation between two states) and CSS keyframes (multi-step animations on a timeline). Both are pure CSS, no JavaScript needed for the basics.

    Talking points

    Restraint is the principle. One or two well-placed animations make a site feel polished. Animations everywhere make it feel like a 2008 Flash site. Pick a few moments (page load, hover, button feedback) and animate those well.

    Transitions are for "from state A to state B" (hover effects, theme changes). Keyframes are for "step 1, step 2, step 3" (entrance animations, looping effects, complex sequences).

    Important note from the prof's syllabus: respect prefers-reduced-motion for accessibility. Some users are sensitive to motion. We add a media query that disables animation for them.

    See easing functions in action

    The same animation feels different depending on its easing curve. Click each button to see the difference.

    transition: transform 1s linear;

    Smooth hover with transitions

    The pattern: declare a transition on the base state, then change the property on hover.

    →
    In styles.css, replace your .photo-grid img rule.
    styles.css · update photo grid images 
    .photo-grid img {
  width: 100%;
  aspect-ratio: 1 / 1;
  object-fit: cover;
  border-radius: 4px;

  /* TRANSITION RULE
     Says: "smoothly animate transform and box-shadow over 0.3s using ease curve"
     Without this, hover changes happen instantly (jarring).
     With it, they fade smoothly. */
  transition: transform 0.3s ease, box-shadow 0.3s ease;
}

.photo-grid img:hover {
  /* On hover, scale up slightly and add a shadow.
     Because of the transition above, this happens smoothly. */
  transform: scale(1.05);
  box-shadow: 0 8px 20px rgba(0, 0, 0, 0.15);
}
    What happens after save and refresh

    Hover any photo in the grid. It scales up smoothly to 105% and lifts off the page with a soft shadow. Move your cursor away, it eases back. The 0.3 second timing makes it feel responsive without being slow.

    A keyframe animation for entrance

    Let's fade and slide elements in when the page loads. Keyframes describe the state at each step (or just from and to). The animation property attaches the keyframes to an element.

    →
    In styles.css, add this to the bottom.
    styles.css · add to bottom 
    /* Define the animation. "fade-in-up" is just a name we picked.
   "from" = starting state, "to" = ending state.
   The browser interpolates between them automatically. */
@keyframes fade-in-up {
  from {
    opacity: 0;                          /* invisible */
    transform: translateY(12px);         /* shifted down 12px */
  }
  to {
    opacity: 1;                          /* fully visible */
    transform: translateY(0);            /* in its natural position */
  }
}

/* Apply the animation:
   - name: fade-in-up (the keyframes above)
   - duration: 0.6s
   - timing: ease-out (slows down at the end) */
header {
  animation: fade-in-up 0.6s ease-out;
}

main section {
  animation: fade-in-up 0.6s ease-out;

  /* "backwards" means: before the animation starts (during the delay),
     show the "from" state. Without this, sections would flash visible
     for a split second before animating in. */
  animation-fill-mode: backwards;
}

/* Stagger the sections so they appear one after another.
   :nth-child(1) is the first section, (2) the second, etc. */
main section:nth-child(1) { animation-delay: 0.1s; }
main section:nth-child(2) { animation-delay: 0.2s; }
main section:nth-child(3) { animation-delay: 0.3s; }
    What happens after save and refresh

    The header fades in from below. Then About appears. Then Gallery. Then Contact. Each one staggered by 100 milliseconds. The whole entrance takes about a second total. It feels designed instead of all-at-once.

    Trigger an animation on a click

    You can also fire animations on user actions by adding/removing a class with JavaScript. Let's wire the surprise button to make the heading shake.

    →
    In styles.css, add the shake keyframes and a trigger class.
    styles.css · add to bottom 
    /* Multi-step keyframe: starts at 0%, hits intermediate states, ends at 100%.
   This bounces the element left and right twice. */
@keyframes shake {
  0%, 100% { transform: translateX(0); }   /* start and end at center */
  25%      { transform: translateX(-6px); } /* a quarter through, left */
  75%      { transform: translateX(6px); }  /* three quarters through, right */
}

/* Apply only when this class is added. */
.shake {
  animation: shake 0.4s ease-in-out;
}
    →
    Update your surprise button handler in index.html.
    index.html · inside $(document).ready 
    $("#surprise-btn").on("click", function() {

  // Add the .shake class. CSS sees it and runs the shake animation.
  $("h1").addClass("shake");

  // Remove the class after the animation finishes (400ms).
  // Why? Without this, clicking again wouldn't re-trigger the animation,
  // because the class is already there.
  setTimeout(function() {
    $("h1").removeClass("shake");
  }, 400);

});

    Respect users who don't want motion

    Some users have motion sensitivity. Browsers expose a prefers-reduced-motion media query that lets us disable animations for them. The prof's syllabus calls this out.

    →
    In styles.css, add this to the very bottom.
    styles.css · accessibility tail 
    /* If the user has set their OS to reduce motion,
   strip out all animations and transitions. */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
    What this does

    For most users, nothing changes, your animations still work. For users who have set "Reduce motion" in their OS settings (System Settings on Mac, or Windows Settings), all animations effectively disappear. Same site, accessible to everyone.

    Quick check
    What is the difference between a CSS transition and a CSS keyframe animation?
    Right answer: B. Transitions interpolate from "current value" to "new value" when something triggers a change. Keyframes let you describe a multi-step animation timeline.
    Quick check
    In a staggered entrance, what does animation-delay: 0.2s do?
    Right answer: B. Delay is the wait time before the animation kicks off. Different delays on different elements create a staggered effect that feels more designed than everything moving in unison.
