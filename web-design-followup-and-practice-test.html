    Module 01 · Session 08 continued

    JavaScript control flow.

    In the first lesson we covered variables and functions. The rest of Session 8 is about how to make decisions (operators, conditionals) and how to repeat actions (loops). Together these are the entire core of programming logic.

    Talking points

    Three concepts, in order: operators (the verbs), conditionals (the decisions), loops (the repetition). Every program is some combination of these three plus variables and functions.

    The one that catches everyone: === vs ==. Always use triple equals in JavaScript. Double equals does sneaky type conversion that causes bugs.

    Operators: math, comparison, logic

    Operators are symbols that act on values. Three families to know.

    JavaScript · operators 
    // MATH OPERATORS
let a = 10 + 5;    // addition, a is 15
let b = 10 - 5;    // subtraction, b is 5
let c = 10 * 5;    // multiplication, c is 50
let d = 10 / 5;    // division, d is 2
let e = 10 % 3;    // modulo (remainder), e is 1


// COMPARISON OPERATORS (always return true or false)
5 === 5            // true  (strict equals)
5 === "5"          // false (different types: number vs string)
5 !== 6            // true  (not equals)
10 > 5             // true  (greater than)
10 < 5             // false (less than)
10 >= 10           // true  (greater than or equal)


// LOGICAL OPERATORS (combine true/false values)
true && false      // false (AND, both must be true)
true || false      // true  (OR, at least one must be true)
!true              // false (NOT, flips the value)
    Quick check
    What does 5 === "5" evaluate to?
    Right answer: B. Triple equals checks both value AND type. The number 5 is not the same type as the string "5", so the result is false. With double equals (==) it would be true because of automatic type conversion, which is exactly why we use triple equals.

    Conditionals: if, else if, else

    Conditionals let your code take different paths based on a condition.

    JavaScript · if / else if / else 
    let score = 85;

// IF / ELSE IF / ELSE chain
// The browser checks each condition top to bottom.
// First one that's true runs. The rest are skipped.
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");           // this runs, since 85 >= 80
} else if (score >= 70) {
  console.log("C");
} else {
  console.log("F");           // default if nothing above matched
}


// SHORTHAND: the ternary operator
// Read as: "if condition, return X, otherwise return Y"
let pass = score >= 70 ? "passed" : "failed";
// pass is now "passed"
    Quick check
    In an if / else if / else chain, what happens if two conditions are both true?
    Right answer: A. JavaScript checks the conditions top to bottom and exits as soon as one is true. That's why order matters in a chain: put your most specific conditions first.

    Loops: for and forEach

    Loops repeat a block of code. Two patterns cover 95% of what you'll do.

    JavaScript · for loop 
    // The classic for loop has 3 parts inside the parentheses:
// 1. let i = 0       initialize a counter
// 2. i < 5           keep going while this is true
// 3. i++             after each pass, increase i by 1

for (let i = 0; i < 5; i++) {
  console.log("Iteration " + i);
}

// Output:
// Iteration 0
// Iteration 1
// Iteration 2
// Iteration 3
// Iteration 4
// (note: counts start at 0 and stop BEFORE 5, so 5 iterations total)
    JavaScript · forEach for arrays 
    // forEach is the modern way to loop over an array.
// Cleaner than a for loop when you have an array.

const colors = ["red", "green", "blue"];

// Run a function for each item in the array.
// The function gets the current item as its argument.
colors.forEach(function(color) {
  console.log(color);
});

// Output:
// red
// green
// blue


// REAL EXAMPLE: turn every <img> on the page red-tinted
const images = document.querySelectorAll("img");

images.forEach(function(img) {
  img.style.filter = "sepia(0.6)";
});
    Quick check
    In for (let i = 0; i < 5; i++), how many times does the loop run?
    Right answer: B. The loop runs while i < 5. So i goes through 0, 1, 2, 3, 4, that's 5 iterations. When i becomes 5, the condition fails and the loop exits.

    Putting it together

    A real example using all three concepts. We'll update the surprise button to count clicks and change its label based on the count.

    →
    In index.html, replace your surprise button click handler with this.
    index.html · inside $(document).ready 
    // Variable (counter) starts at 0
let clickCount = 0;

$("#surprise-btn").on("click", function() {

  // OPERATOR: increment the counter by 1
  clickCount = clickCount + 1;

  // CONDITIONAL: change the label based on the count
  if (clickCount === 1) {
    $(this).text("Click me again");
  } else if (clickCount < 5) {
    $(this).text("Click " + clickCount + " of 5");
  } else {
    $(this).text("OK that's enough");
  }

  // The original toggle still happens every click
  $("#about").toggleClass("highlighted");

});
    What happens after save and refresh

    First click: button label becomes "Click me again," About section turns yellow. Second click: label becomes "Click 2 of 5," About turns off. Third: "Click 3 of 5." Fourth: "Click 4 of 5." Fifth and beyond: "OK that's enough."

    You used a variable to track state, an operator to update it, and a conditional to decide what to display. That's most of what programming is.

    Quick check
    Which operator combines two conditions where BOTH must be true?
    Right answer: C. Double ampersand is logical AND. Double pipe (||) is OR (at least one true). Exclamation (!) is NOT (flips the value). Plus is for addition or string joining.

    HTML tables, properly.

    The first lesson gave you a quick table cheat sheet. Session 9 actually has more to it. Tables are for tabular data only (a logical presentation of rows and columns), never for page layout. CSS Grid replaced tables for layout 15 years ago.

    Talking points

    Two things to drive home: tables are ONLY for spreadsheet-style data (schedule, price comparison, results), and the thead/tbody/tfoot grouping is what makes them semantic and accessible.

    The styling defaults are ugly. border-collapse: collapse is the one CSS line that fixes 80% of it. The rest is just padding and color.

    The table structure

    HTML · tables fully structured 
    <table>

  <!-- caption: a title for the table, shown above it.
       Required for accessibility. Screen readers announce it. -->
  <caption>Project schedule</caption>

  <!-- thead: groups the header rows together -->
  <thead>
    <tr>
      <!-- th = "table header" cell. Browser bolds these by default. -->
      <th>Week</th>
      <th>Topic</th>
      <th>Due</th>
    </tr>
  </thead>

  <!-- tbody: groups the data rows -->
  <tbody>
    <tr>
      <!-- td = "table data" cell, the normal cell -->
      <td>1</td>
      <td>Setup</td>
      <td>Sept 5</td>
    </tr>
    <tr>
      <td>2</td>
      <td>Wireframes</td>
      <td>Sept 12</td>
    </tr>
  </tbody>

  <!-- tfoot: groups footer rows (totals, summaries) -->
  <tfoot>
    <tr>
      <td colspan="2">Total weeks</td>
      <td>14</td>
    </tr>
  </tfoot>

</table>

    Important attribute: colspan="2" makes a cell span 2 columns. There's also rowspan for spanning rows.

    Quick check
    What is the difference between <th> and <td>?
    Right answer: A. th stands for "table header." Browsers style it differently (bold, centered) and screen readers announce it as a header. Use it for the first row, or first column if your table has row headers.

    Make it not look like 1998

    →
    In styles.css, add this to the bottom.
    styles.css · table styles 
    table {
  /* THE ONE LINE that fixes ugly table borders.
     By default, each cell has its own border with a gap between them.
     "collapse" merges adjacent borders into one clean line. */
  border-collapse: collapse;

  width: 100%;                    /* fill the container */
  margin: 24px 0;
}

caption {
  text-align: left;
  font-weight: bold;
  margin-bottom: 8px;
  font-size: 18px;
}

/* Style header AND data cells together, then override below if needed */
th, td {
  padding: 12px 16px;             /* breathing room inside each cell */
  text-align: left;
  border-bottom: 1px solid #ddd;
}

th {
  background: #f0f0f0;
  font-weight: bold;
}

/* Alternating row colors using :nth-child.
   "even" matches the 2nd, 4th, 6th rows. Much easier to read. */
tbody tr:nth-child(even) {
  background: #fafafa;
}

/* Hover effect (optional but nice) */
tbody tr:hover {
  background: #f5f5e8;
}
    What happens after save and refresh

    A clean table with a bold header row, alternating zebra-stripe backgrounds on the data rows, and a subtle hover effect. Every row has consistent padding so the columns line up. The caption sits above as a label.

    Quick check
    What does border-collapse: collapse do?
    Right answer: B. Without it, each cell has its own border and you see a double line at every boundary. With it, adjacent borders merge into a single clean line. This is one of those CSS one-liners that immediately makes a table look modern.

    Spanning cells with colspan and rowspan

    HTML · spanning attributes 
    <table>
  <tr>
    <th>Item</th>
    <th>Q1</th>
    <th>Q2</th>
  </tr>
  <tr>
    <td>Sales</td>
    <!-- This cell spans 2 columns instead of 1.
         The next row will only need 2 cells (1 + 1 spanned = 3 columns). -->
    <td colspan="2">Combined Q1 + Q2: $50k</td>
  </tr>
</table>
    Quick check
    When should you use an HTML table?
    Right answer: C. Tables are for tabular data: schedules, comparisons, results, spreadsheet-style information. Using tables for page layout is a 1990s practice that screen readers can't handle properly. Use CSS Grid or Flexbox for layout.
    Module 03 · Session 12

    CSS frameworks, a quick tour.

    A CSS framework is a pre-written stylesheet (sometimes with JavaScript) that gives you ready-made components and utilities. Instead of writing your own button styles, grid system, and navigation, you use the framework's. Saves time, costs you some uniqueness.

    Talking points

    You don't need to know how to USE every framework. You need to know what frameworks ARE, the two main styles, and the trade-offs. That's the level of question the prof's exam will ask.

    Two flavors to know: component-based (Bootstrap, Bulma, Foundation) gives you pre-styled chunks like "card" or "navbar". Utility-based (Tailwind) gives you tiny atomic classes you combine. Both have their place.

    Pronunciation Bulma "BUHL-muh" Tailwind "TAIL-wind"

    Two flavors

    Component-based (Bootstrap, Bulma, Foundation)

    You add a class like btn btn-primary and get a fully styled button. The framework decided what a button looks like. Faster to start, harder to make it look unique.

    <!-- Bootstrap example -->
<button class="btn btn-primary">Save</button>
<div class="card">
  <div class="card-body">Pre-styled card</div>
</div>

    Utility-based (Tailwind CSS)

    You add many small classes like px-4 py-2 bg-blue-500 text-white rounded. Each class does one thing. More verbose in HTML, but you control every detail.

    <!-- Tailwind example -->
<button class="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600">
  Save
</button>
    Quick check
    What is the main difference between Bootstrap and Tailwind CSS?
    Right answer: C. Bootstrap hands you finished components and you accept its design choices. Tailwind hands you tiny building blocks and you assemble your own design. Both are free and modern.

    Pros and cons

    + Speed: get a working UI in minutes, not days
+ Consistency: every button looks like every other button
+ Mobile-first: responsive breakpoints are built in
+ Community: huge ecosystem, templates, tutorials, plugins
+ Accessibility: most modern frameworks have it baked in
+ Browser compatibility: tested across browsers for you
+ Documentation: every class and component is documented
    - Bloat: you load CSS for components you'll never use
- Sameness: lots of sites look like the framework's template
- Learning curve: you trade learning CSS for learning class names
- Customization: changing the look feels like fighting the framework
- HTML clutter: utility frameworks fill your markup with classes
- Version churn: major version upgrades can break your site
- Overkill: a small site rarely needs a full framework

    When to reach for a framework

    • Yes: rapid prototyping, internal admin tools, hackathons, time-pressure projects
    • Yes: teams without a designer where consistency matters more than uniqueness
    • Maybe: mid-size projects where you'll customize a lot, lean toward Tailwind
    • No: brand-driven sites where visual identity is the point (a portfolio, an agency, a brand)
    • No: small static sites where the framework would be larger than your site
    Quick check
    Which is a typical downside of using a CSS framework?
    Right answer: C. When everyone uses the same framework without customizing it, sites start to look alike. The "Bootstrap look" was a real thing in the mid 2010s. The other options are actually upsides of frameworks, not downsides.

    Frameworks you'll see named

    • Bootstrap. The original. Component-based. Still the most popular for traditional websites.
    • Tailwind CSS. Utility-based. The trendy choice for the last few years. Lots of marketing sites use it.
    • Bulma. Component-based, pure CSS (no JavaScript required). Cleaner-looking defaults than Bootstrap.
    • Foundation. By Zurb. Old, enterprise-leaning. Less common in 2026.
    • Spectre. Lightweight component framework. Niche.
    Quick check
    Which approach does Tailwind CSS use?
    Right answer: B. Tailwind is the headline utility-based framework. Bootstrap, Bulma, and Foundation are component-based.

    Canvas, the drawing surface.

    The <canvas> element is a transparent rectangle on the page that you draw on using JavaScript. The browser doesn't draw anything by itself, you have to issue drawing commands in JS. Used for games, data viz, interactive graphics, anything dynamic.

    Talking points

    The key distinction Jack needs to know: SVG is vectors (you describe shapes once, browser keeps them sharp). Canvas is pixels (you paint on a bitmap, faster for lots of moving things, but doesn't scale).

    The big four rules of canvas: 1) without JS, canvas does nothing, 2) canvas drawings are pixels, not DOM elements, so you can't style them with CSS or grab them with jQuery, 3) you must get the "2d context" to draw, 4) once drawn, it stays until you clear or overdraw it.

    p5.js is a friendlier wrapper that the prof links. Worth mentioning, not deep-diving.

    Pronunciation canvas "KAN-vuhs" context "KON-text"

    Canvas vs SVG

    + Stays sharp at any zoom level
+ Each shape is a DOM element you can style with CSS
+ Easy to make accessible
+ Good for icons, logos, charts, diagrams

- Slow with thousands of moving shapes
- Files can get large for complex art
    + Fast even with thousands of moving things
+ Good for games, particle effects, video filters
+ Lower memory for big complex scenes
+ Pixel-level control

- Blurry when scaled up
- Drawings are not DOM elements (no CSS, no jQuery)
- Harder to make accessible
    Quick check
    What is the main difference between SVG and Canvas?
    Right answer: B. SVG describes shapes (a circle has a center and radius, scales perfectly). Canvas paints pixels (you draw a circle once, and the result is just colored pixels, no longer a "circle" the browser tracks). The other options are backward: Canvas needs JavaScript to do anything, both work in all browsers, and SVG predates Canvas.

    The canvas pattern

    Every canvas drawing follows the same three steps: add the element, get its 2D context, issue drawing commands.

    index.html · add a canvas anywhere 
    <!-- The canvas element. width and height are in pixels.
     Text inside is fallback for browsers that don't support canvas.
     The id lets JavaScript find it. -->
<canvas id="my-canvas" width="400" height="200">
  Your browser does not support canvas.
</canvas>
    JavaScript · the three-step drawing pattern 
    // STEP 1: find the canvas element
const canvas = document.getElementById("my-canvas");

// STEP 2: get the 2D drawing context.
// "2d" is the most common. WebGL ("webgl") is for 3D graphics.
// The context is the object you call drawing commands on.
const ctx = canvas.getContext("2d");

// STEP 3: draw things.

// Set the fill color (used by fill commands below)
ctx.fillStyle = "tomato";

// Draw a filled rectangle: x, y, width, height.
// Coordinates start at top-left (0, 0).
ctx.fillRect(10, 10, 100, 50);


// Switch fill color, draw text
ctx.fillStyle = "black";
ctx.font = "20px Georgia";
ctx.fillText("Hello canvas", 130, 45);


// Draw a circle. Canvas circles are made with arc().
// arc(x, y, radius, startAngle, endAngle) where angles are in radians.
// 0 to Math.PI * 2 is a full circle.
ctx.beginPath();                       // start a new shape
ctx.arc(300, 100, 40, 0, Math.PI * 2);
ctx.fillStyle = "steelblue";
ctx.fill();                            // fill the path with the current color
    What this draws

    A 400 by 200 pixel rectangular area with: a tomato-colored rectangle in the top-left, the text "Hello canvas" in black next to it, and a blue circle to the right. Once drawn, those pixels just sit there. They're not DOM elements, so right-clicking on the circle and choosing "Inspect" won't show you a <circle> tag.

    Quick check
    What method do you call to get the drawing context for a canvas?
    Right answer: B. getContext("2d") returns the object you call all your drawing methods on (fillRect, arc, fillText, etc). For 3D graphics you'd use getContext("webgl") instead.

    p5.js, the friendlier wrapper

    p5.js is a JavaScript library built on top of canvas. It gives you a simpler API designed for artists and beginners. The prof's syllabus calls it out specifically.

    JavaScript · same circle, in p5.js 
    // Two functions: setup() runs once, draw() runs 60 times per second.
function setup() {
  createCanvas(400, 200);     // creates and sizes the canvas for you
  background(240);            // light gray background
}

function draw() {
  fill("steelblue");
  noStroke();
  circle(300, 100, 80);       // x, y, diameter, no Math.PI nonsense
}

    You won't need p5 for the exam, just recognize the name and know it's an easier way to use canvas for creative coding.

    Quick check
    Why CAN'T you grab shapes drawn on a canvas with jQuery?
    Right answer: C. Once you draw on a canvas, the result is just colored pixels in a bitmap. The browser doesn't remember "there's a circle here" or "there's text here." Compare to SVG, where every shape is a real DOM element you can target with CSS, jQuery, or document.getElementById.
    Module 05 · Session 11

    Usability and user testing.

    Usability is a quality attribute that assesses how easy a user interface is to use. The prof leans heavily on this in Session 11. He runs an in-class user testing exercise. Your Vision Document is supposed to address it. This module is the vocabulary you need.

    Talking points

    Usability has a real academic source: the Nielsen Norman Group (NNG). The prof links them directly. If you ever see "NN/g" cited on a quiz, that's them.

    The key distinction the prof emphasizes: Findability vs Discoverability. Findability is "I'm looking for X, can I find it?" Discoverability is "I didn't know X existed, did I stumble onto it?" Both matter. They require different test methods.

    The principle to remember: iterative testing. You don't test once at the end. You test small things often, fix, retest.

    What usability means

    The classic NNG definition: usability is how easy a user interface is to use, AND the methods for improving ease-of-use during the design process. So it's both a property of the design AND the practice of making it better.

    Five dimensions NNG uses:

    • Learnability. How easy is it for first-time users?
    • Efficiency. Once learned, how fast can users do tasks?
    • Memorability. If they come back later, do they remember how?
    • Errors. How often, how severe, and how easily can they recover?
    • Satisfaction. How pleasant is it to use?
    Quick check
    Which group is associated with the formal definition of usability the prof references?
    Right answer: C. The Nielsen Norman Group (NN/g) defined usability in this academic sense. The prof links directly to their site for the canonical definition.

    Findability vs Discoverability

    Findability

    The user is actively looking for something. Can they find it? Test by giving them a task ("find the contact form") and watching how long it takes.

    Improved by: clear navigation, search, consistent labels, logical hierarchy.

    Discoverability

    The user doesn't know a feature exists. Will they come across it? Test by NOT telling them about features and seeing which ones they find on their own.

    Improved by: visual prompts, onboarding hints, smart defaults, features placed where users already are.

    Quick check
    A user knows they want to email customer support and looks for the contact link. This is a test of:
    Right answer: A. The user is actively searching for a known thing. Findability is "I'm looking for X, can I find it?" If you were testing whether they noticed a feature they didn't know about, that would be discoverability.

    How to run a basic user test

    The prof's in-class exercise follows this rough pattern. You'll be expected to know the structure.

    1
    Pick tasks tied to your user stories
    "Sign up for the newsletter" and "Find the lead designer's bio" beat "Look around and tell me what you think."
    2
    Sit with the tester, ask them to think aloud
    You want their reasoning. "I'm clicking this because I expect a menu." Catches assumption mismatches.
    3
    Don't lead them, don't rescue them
    If they get stuck, that's data. Let them fail unless they're truly suffering. Resist the urge to explain.
    4
    Note where they hesitate, click wrong, or backtrack
    Those are your fix-list. Fast clicks mean the design is working.
    5
    Fix one thing, test again with a new person
    This is "iterative testing." Tiny rounds, often. The opposite of one big test at the end.
    Quick check
    What does "iterative testing" mean?
    Right answer: C. The iterative part is the cycle: test something small, learn what's broken, fix it, test again with someone fresh. Beats one big test at the end where you find ten problems and can't fix them all.

    User-centered design principles

    From the article the prof links (Maze). These four values guide the whole process:

    • Value 1: Early and frequent user involvement minimizes costly mistakes.
    • Value 2: Empathizing with users helps solve real problems.
    • Value 3: Clarity and consistency are key for intuitive designs.
    • Value 4: User data and insights drive decisions.
    Quick check
    What should you do when a user gets stuck during a usability test?
    Right answer: D. The moment a user gets stuck is the most valuable data in the test. Rescuing them hides the real problem. Let them struggle, write down what they try, and ask them what they expected to happen.
    Module 06 · The Final

    The final presentation.

    Your final is a 10-minute (max) presentation plus a Vision Document PDF. The prof gave the exact rubric in Session 11. This module is that checklist, translated into what you actually need to prepare and say.

    Talking points

    This is the most important module of the follow-up. Not code, structure. Jack's grade is built on this checklist. Read it with him slowly.

    Frame each item as a question he should answer in 30 to 60 seconds during the presentation. Practice each one out loud with him if there's time.

    Two physical deliverables: the live site link and the Vision Document PDF. Both must be sent before or during the presentation. Confirm he has both ready.

    The 10-item Vision Document checklist

    Each item below is a section your Vision Document and presentation should cover. The bold question is what your section should answer. The dim text is what to actually say in your 30 to 60 seconds.

    1. The Big Idea: Concept, User Personas, User Stories

    What is this project and who is it for?

    State the project in one sentence. Then identify 1 to 3 user types ("personas"). For each, write a user story in the form: "As a [persona], I want to [do something] so that [outcome]." Example: "As a prospective client, I want to see Jack's past work so I can decide whether to hire him."

    2. Organizing Content / Sitemaps

    How is the content organized?

    Show a simple tree or list of pages and sections. Explain why you grouped things the way you did. "Gallery is at the top because clients care about work samples first. Contact is at the bottom because they only need it after they've decided."

    3. Typography

    What fonts did you pick and why?

    Name your fonts. Explain the choice. "I'm using Georgia for body because it reads well in long blocks and feels established. The serif sets a tone of craft and seriousness."

    4. Composition / Layout

    What device are you designing for first?

    Mobile-first, tablet-first, or desktop-first. Why. Mention specific layout decisions: max-width, where things stack on small screens, etc.

    5. Design Principles

    Which principles are you leveraging?

    Pick 2 to 3 from the prof's list and point to where you used each one:

    • Dominance. One element clearly the most important.
    • Similarity. Related items look alike.
    • Rhythm. Repetition creates pacing.
    • Texture. Surface variety adds depth.
    • Direction. Visual flow guides the eye.
    • Contrast. Differences create emphasis.

    6. Sketches and Layout

    What did you sketch, what was your moodboard?

    Include early sketches, wireframes, or any moodboard/inspiration images in the PDF. Even rough notebook scribbles work. Shows your process.

    7. Color

    What color scheme did you choose and why?

    Name the palette (3 to 5 colors usually). Explain the mood it sets. "Warm neutrals with a single accent in burnt orange. Friendly, designer-y, doesn't compete with the work samples."

    8. JavaScript, Interactivity, Forms

    How is interactivity helping your users?

    For each interactive feature on your site (gallery slider, theme toggle, contact form, hover effects), explain WHY it's there. "The slider lets users browse work without scrolling. The form has validation so they don't submit blank messages." Don't just list, justify.

    9. User Testing and Usability

    What did testing reveal, what did you change?

    Summarize the test you ran in Session 11 and the changes that came from it. "My partner couldn't find the contact link on mobile. I moved it to a sticky button at the bottom. Retested with another classmate, fixed."

    10. The Final Outcome

    What did you learn, what would you do next?

    Reflection. What was harder than expected. What you'd add with more time. What you're proud of. Closes the loop.

    Quick check
